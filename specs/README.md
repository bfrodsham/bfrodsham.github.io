# Specs

Spec-driven development using the GitHub Spec Kit layout. Read [constitution.md](constitution.md) first.

Each feature folder contains:
- `spec.md` – what and why: user stories, Given/When/Then scenarios, numbered requirements, edge cases, success criteria, open questions.
- `plan.md` – how: technical design and decisions.
- `tasks.md` – ordered, checkable implementation tasks.

| Feature | Summary |
|---|---|
| [001-landing-page](001-landing-page/spec.md) | Page composition, layout, shared non-functional requirements |
| [002-header](002-header/spec.md) | Header navigation with stubbed links |
| [003-introduction](003-introduction/spec.md) | Intro section with placeholder content |
| [004-recent-commits](004-recent-commits/spec.md) | "What am I up to?" table of latest public commits |

`[NEEDS CLARIFICATION]` marks open questions to resolve before implementing the affected item. None are currently open.
